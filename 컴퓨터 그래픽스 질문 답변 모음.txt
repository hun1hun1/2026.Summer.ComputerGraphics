함수와 변수 기초 문제
3. 매개변수의 역할은 무엇인가?
A: 외부함수를 호출할 때 전달받은 값을 함수 내부에서 사용할 수 있도록 받아 저장하는 변수

4. 아래항목을 각각 설명하여라.
Call By Value: 함수를 호출할 때 매개변수를 값으로 전달하는 경우로 값이 복사되기 때문에 원본을 변경할 수 없다.
Call By Reference: 함수를 호출할 때 매개변수를 주소값으로 전달하는 경우로 값이 복사되는 것이 아닌 값을 참조하기 때문에 원본을 변경할 수 있다.

배열과 포인터 기초 문제
1. 배열의 인덱스는 왜 0부터 시작할까?
A: 배열의 이름이 첫 인덱스의 주소값을 가르키기 때문에 메모리 주소 계산을 효율적으로 하기 위해서 0부터 시작함.

2. 배열은 왜 배열을 일렬로 생성하는가?
A: 인덱스를 이용한 주소 계산만으로 각 요소에 O(1)의 시간으로 빠르게 접근할 수 있도록 하기 위해서이다.

3. 배열은 왜 크기를 상수로 지정하거나 초기화를 해야하는가?
A: 배열은 연속된 메모리 공간을 사용하므로, 컴파일러가 배열의 크기만큼 메모리 공간을 확보해야하는데, 배열의 크기를 변수로 지정하면 컴파일 시점에는 변수의 값을 알 수 없기 때문에 컴파일러가 메모리를 얼마나 확보해야 하는지 알 수 없다.

4. 배열은 왜 복사할 때 반복문을 이용해야 하는가?
A: 배열 전체를 하나의 값으로 취급하지 않기 때문에 대입 연산을 지원하지 않기 때문이다.

5. memcpy() 함수는 반복문을 이용한 복사와 무엇이 다른가?
A: memcpy() 함수는 사용자가 지정한 메모리 크기만큼 바이트 단위로 한 번에 복사하여 다른 배열에 전달한다. 단순한 메모리 복사에 적합하다.

배열과 포인터와 함수 응용 문제
1. 2차원 배열에서 x값이 지정 해야 하지만, y값을 지정할 필요가 없는 이유는 무엇인가?
A: 배열의 총 크기를 x값으로 나누면 y값이 나오기 때문이다. 2차원 배열은 연속된 메모리에 저장되므로, 한 차원의 크기를 알면 전체 크기와 자료형의 크기를 이용하여 나머지 차원의 크기를 계산할 수 있음.

2. 1차원 배열을 2차원 배열로 쓸 수 있는 이유는 무엇인가?
A: 1차원이든 2차원이든 배열은 연속된 메모리에 저장되기 때문에 2차원 배열도 사실상 1차원 배열처럼 저장되기 때문이다.

3. 문자열 복사할 때, 사이즈를 받지 않는 이유는 무엇인가?
A: 문자열은 마지막에 '\0'을 저장하여 끝을 표시하기에 사이즈를 받지 않아도 알 수 있다.

4. 문자열에 널문자가 없는 경우 어떤 문제가 발생 할 수 있는가?
A: 문자열의 끝을 알 수 없다. 따라서 문자열 관련 함수가 배열의 범위를 넘어 메모리를 계속 읽어서 잘못된 출력, 메모리 접근 오류 등이 발생할 수 있음.

연결 리스트

연결 리스트 기초 문제
1. 포인터는 무엇인가?
A: 포인터는 주소값을 저장하는 변수이다. 저장된 주소를 통해 해당 변수의 값에 접근하거나 변경할 수 있다.

2. 동적/정적할당의 차이를 설명하여라.
A: 정적할당은 컴파일 시점에 메모리 크기가 결정되는 방식이고, 동적할당은 런타임 시점에 필요한 만큼 메모리를 할당하는 방식이다. 동적할당한 메모리는 사용 후 직접 해제해야 한다.

3. 포인터와 동적할당의 관계를 설명하여라.
A: 동적할당은 런타임 시점에 이름이 없는 메모리 공간을 생성한다. 따라서 포인터가 할당된 메모리의 주소값을 저장해야만 해당 변수에 참조, 접근, 수정 등이 가능하다.

4. 매개변수의 역할은 무엇이가?
A: 연결 리스트에서 매개변수는 시작(혹은 끝)노드의 주소를 매개변수로 전달하여 삽입, 삭제 등의 작업을 할 수 있도록 한다.

연결 리스트 심화 문제
1. 포인터를 매개변수로 전달받았을 때 어떻게 포인터가 원본포인터의 주소값을 변경할 수 있는가?
A: 원본포인터의 주소값을 변경하려면 매개변수로 이중포인터를 받아야한다. 즉 포인터의 주소를 매개변수로 받아야 원본 포인터의 주소값을 변경할 수 있다.

큐와 스택 심화 문제
1. 큐와 스택을 연결리스트와 배열로 구현 시, 각자의 장단점을 활용 용도를 고려하여 서술해보자.
연결리스트 구현 시 장점: 크기를 미리 정할 필요가 없다 그러므로 메모리 낭비가 적다, 삽입과 삭제가 빠름.
연결리스트 구현 시 단점: 각 노드마다 다음 노드의 주소 저장을 위한 추가 메모리 필요, 메모리가 연속되지 않아 캐시 효율이 낮음, 인덱스로 접근 할 수 없음.
배열로 구현 시 장점: 구현이 단순하다, 메모리 사용 효율이 높다, 데이터 접근 속도 빠름.
배열로 구현 시 단점: 크기를 미리 정해야 함, 메모리 낭비 발생 가능, 크기를 동적으로 변경하기 어려움.

정렬

실습 및 문제
1. 점근식 표기법(Big-O)는 무엇이며 왜 사용하는가?
A: 알고리즘의 입력 데이터의 크기가 증가할 때 시간 복잡도와 공간 복잡도가 어떤 비율로 증가하는지 표현하는 표기법으로 해당 알고리즘이 시간적 혹은 공간적으로 효율적인지 비효율적인지 비교하는 척도이다.

2. 정렬은 왜 필요하고 중요한가?
A: 데이터를 더 빠르고 효율적으로 처리하기 위해서이다. 데이터 검색과 관리의 효율성을 높이고 다른 알고리즘의 수행을 가능하게 함.

이진트리

이진트리 기초 문제
1. 만들어진 힙트리는 어떤 종류의 힙트리인가?
A: min heap이다.

2. 데이터를 왜 최소값부터 추가 했을까?
A: min heap은 부모가 자식보다 작은 값이어야 하므로 최소값부터 추가 시 힙 재구성 과정이 줄어들 수 있다.

3. 최대값부터 데이터가 들어온다면, 어떤 힙트리를 활용하는 것이 좋은가?
A: max heap

이진트리 심화 문제
1. 이진트리에서 재귀구조를 사용하는 이유는 무엇인가?
A: 이진트리는 작은 크기의 이진트리로 반복되는 구조를 가지고 있기 때문이다. 재귀함수를 이용하면 동일한 작업을 서브트리에 반복 적용할 수 있음.

3. 이진트리에서 재귀구조를 이용하지 않고, 순회를 구현하려면 스택이 필요하다. 이유는 무엇인가?
A: 순회 방식에 따라 순회하며 해당 노드에서 순회가 끝나면 부모 노드로 돌아가야 하기 때문에 방문해야 할 노드와 부모 노드를 저장해야 하므로 스택을 사용해야 한다.

4. 레드블랙이진트리는 무엇인가? 어떤 특징을 가지는가?
A: 레드블랙 이진트리는 균형을 유지하는 트리로 중간 값이 루트 노드가 되는 구조이다. 규칙에 따라 트리를 재구성하므로 트리의 레벨을 log n으로 유지한다.
